VM2Backup - резервное копирование виртуальных машин (VMware ESXi / vCenter / папки) в папку, FTP, FTP поверх TLS и SCP
===========================================================================================================================

1. Установка
   - Запустите VM2Backup-Setup.exe (запросит права администратора). Он сам выберет 64- или 32-разрядный установщик.
   - По желанию: «Ярлык на рабочем столе», «Ярлык в меню Пуск», «Запустить службу резервного копирования сейчас».
   - Нажмите «Установить» («Обновить», если программа уже стоит). Программа ставится в C:\Program Files\VM2Backup\
     (VM2Backup.exe — панель управления, VM2BackupService.exe — служба Windows «VM2Backup Service», она выполняет задачи по расписанию,
     даже когда никто не вошёл в систему) и появляется в «Параметры > Приложения».
   - Для сценариев: VM2Backup-Setup.exe /install /silent [/nostart] [/desktop-] [/startmenu-]   (код возврата 0 — успех)

2. Первое использование
   - Программа (VM2Backup.exe) — небольшая панель управления: показывает, работает ли служба, её версию, папку данных и состояние
     веб-сайта, запускает / останавливает / перезапускает службу, открывает папку журналов и задаёт язык.
   - Вся работа выполняется в веб-интерфейсе: нажмите «Открыть веб-интерфейс» или откройте https://127.0.0.1:8443/ в браузере
     (логин по умолчанию admin / admin; сразу смените пароль). Браузер предупредит о самоподписанном сертификате. Там добавляются серверы
     (источники: VMware ESXi / vCenter или папка с виртуальными машинами; места для бэкапов: FTP / FTP поверх TLS / SCP / сетевые папки;
     «Local Computer» уже есть), делаются бэкапы (уровень сжатия xz 1 ... 9, шифрование AES-256-GCM, размер тома, ограничение скорости),
     задачи с расписанием и окнами времени, восстановление и история. Бэкап, прерванный потерей связи, продолжается с последнего
     готового тома (в том числе после перезапуска службы); проверка и восстановление продолжаются так же.
   - Сетевая папка — это сервер «Network folder (SMB)»: \\сервер\ресурс[\папка], пользователь (ДОМЕН\имя, имя@домен или локальный) и
     пароль (хранится зашифрованным DPAPI и больше не показывается). См. раздел 5.
   - Потерян доступ к веб-сайту (забыт пароль, неверный порт): VM2BackupService.exe /reset-web.

3. Удаление
   - VM2Backup-Setup.exe > «Удалить» или uninstall.cmd от администратора. Настройки, история и бэкапы остаются (C:\ProgramData\VM2Backup).

4. Журналы и данные
   - C:\ProgramData\VM2Backup\ : config.json (пароли зашифрованы DPAPI), history.json, logs\ (service.log, program.log).

5. Сетевые папки (SMB) и сетевые диски
   - Служба работает от SYSTEM (или от указанной учётной записи) в своём сеансе. Она НЕ видит буквы дисков, подключённые вами (Z:), а без
     имени пользователя ходит на другие компьютеры от имени учётной записи компьютера. Поэтому сетевая цель — это UNC-путь
     (\\сервер\ресурс\папка) со своими именем и паролем: служба подключается через WNetAddConnection2 (без буквы диска), пишет
     через это подключение и отключает его, когда объект цели уничтожен. После потери связи подключение восстанавливается, а бэкап
     продолжается с последнего готового тома, как с FTP.
   - Пустое имя пользователя = права учётной записи службы. Windows допускает один набор учётных данных на сервер и сеанс: если к тому же
     серверу уже есть чужое подключение с другими данными, программа сообщит об этом (ошибка 1219) и не будет его разрывать.
   - Обычная буква диска, которой служба не видит, даёт ошибку «drive Z: is not available to the service: use the UNC path».
   - «Test connection» подключается, пишет и удаляет маленький файл и показывает свободное место.
   - Защита от блокировки учётной записи: сервер, отказавший в учётных данных (неверный, заблокированный, отключённый или истёкший пароль), больше не опрашивается запуском по расписанию, пока не изменена
     запись сервера или на странице Datacenter не нажато «Try again» (одно обращение с неверным паролем стоит доменной учётной записи два неудачных входа, и устаревший пароль заблокировал бы её за несколько запусков).
   - По сети данные шифруются, только если общий ресурс требует шифрования SMB 3: для важных данных включайте шифрование самого бэкапа.
   - Проверено на настоящей Windows 10 (x86, 22H2) с ресурсом Samba с логином и паролем (docs/WINDOWS-TESTS.md, группа smbreal): бэкап / проверка /
     восстановление, неверный пароль (понятное сообщение, ошибка 1326, без повторов), недоступный сервер (ждёт и повторяет), несуществующий ресурс
     (ошибка 67, без повторов), сервер остановлен посреди бэкапа и запущен снова (бэкап продолжается), обзор сети с учётными данными, диск, подключённый
     через "net use" (виден с UNC-путём), команды службы. НЕ проверено: доменный ресурс (ДОМЕН\имя и имя@домен), учётная запись службы и пользователь
     программы (ресурс, доступный только вам), шифрование SMB 3, длинные пути и не-ASCII имена на ресурсе.
